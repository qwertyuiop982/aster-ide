# Aster website 5.3 — quiet interface, tactile devices

Bilingual, statically generated website. The homepage contains one **Aster** heading, one exactly centered download button, four closely grouped, depth-separated conceptual phone models and six small footer links. Explanations live on separate pages; there is no Agent demo/workbench on the homepage.

## Build and local checks

```sh
node website/v5/test_language.js
python3 website/v5/build.py --release-dir /path/to/release-v1.06-aster --output /tmp/aster-site-v5
python3 -m http.server 8137 --bind 127.0.0.1 --directory /tmp/aster-site-v5
```

`build.py` uses the Python standard library. It verifies the signed APK's size and SHA-256 against `delivery.json`, generates Chinese/English home, why, help, credits, licenses, about and privacy pages plus a bilingual 404, checks internal links and hashes every published file in `site-manifest.json`. `/` selects device language unless a manual preference is saved; explicit `/zh/` and `/en/` URLs remain stable. Manual language links work without storage.

## Interactive scene

`scene.js` imports self-hosted **Three.js 0.187.0**. `assets/vendor/provenance.json` records the npm tarball and SHA-512 integrity; the MIT text is included. No runtime CDN, remote HDR, analytics, inline script/style or image-search assets are required. The scene works with the existing `script-src 'self'` / `style-src 'self'` / `img-src 'self' data:` policy.

- Four independently drawn silhouette models, not official manufacturer assets or endorsements. Two front-facing home/editor screens are vector redraws based on the supplied Aster UI screenshots (1440×3224 rasterization; generated by `render_screens.py`, not native screenshots). The other two retain the supplied 720×1612 JPEGs. Original JPEGs are retained for provenance/fallback; they are not falsely upscaled as new detail. Product-search images were only visual references and are not distributed.
- Device-only physical materials: beveled metal rails, toroidal camera lips, recessed optics and curved coated lens glass, a leather bump texture and a softbox environment. The background is pure black, with orange-red light from the upper right and restrained cool fill. Text and navigation remain flat and modern.
- Drag to rotate, wheel or two pointers to zoom, hold background for 440 ms to fade/blur the interface to 5%, remove the device presentation blur and switch to a higher-resolution render (up to 3×, constrained by a 10 MP detail budget); release to restore. Arrow keys, `+`/`-`, Space, I (sharp inspection), R and Escape provide keyboard equivalents.
- Pause/reset controls, reduced-motion and data-saver defaults, page visibility suspension, a 1.8–2× presentation canvas and a 30 fps render budget. Inspection pauses auto-rotation; high-DPI detail mode is separate from the deliberate default soft-focus filter. Static geometry is batched by material (49 scene draw calls in browser QA).
- Responsive portrait/landscape composition and a CSS poster when WebGL2 is unavailable or lost. No persistent framebuffer is enabled in production.

## Content and licenses

`locales.json` stores shared bilingual labels; `pages.json` stores explanatory documents and the current Free Go adjustment plus the two model entries. The component inventory is derived from the actual repository notices and retained license/provenance files. No API credentials are published.

APK buttons use the `v1.06-aster` GitHub Release and its exact `app-release.apk` asset through the existing gh-proxy.org prefix. No APK, source archive, API key, deployment credential or account management interface is published.

## Deployment

`deploy_remote.py` verifies the archive and complete static manifest, backs up the previous target, atomically switches `/var/www/aster/current`, checks bilingual routes and assets, and rolls back on failure. Nginx configuration and protected backend routes must remain unchanged. SSH transport and authentication are supplied externally; never put credentials in this directory.

## Visual regression notes (5.3)
- Homepage and document pages share a restrained dark palette, plain typography, thin separators and generous reading margins. No content expansion or decorative cards.
- Four-phone layouts reserve actual three-dimensional clearance; projected overlap is intentional, geometry intersections are not. `data-collisions` and `data-clearance` are computed from conservative per-material bounds in cluster-local space. A common rigid transform preserves that clearance at every rotation/zoom.
- Regenerate the two vector screens with `python3 website/v5/render_screens.py`; verify layouts with `node website/v5/test_scene.mjs`. Neither script is shipped as a public asset.
- CSS fallback retains hold-to-focus; keyboard I toggles sharp inspection and Escape returns. Reduced-motion users get immediate transitions rather than forced animation.
- The original code/conversation JPEGs cannot recover missing detail. For pin-sharp code at extreme zoom, new high-resolution native screenshots are still required.
